# Phase 1 server session and MFA prerequisite

16 October 2026. Owners: Uchi Chinyama and Mumba Chitonge.
Status: locally verified internal foundation; no production caller or credential.

createStepUpVerifier first sends the same bearer token through the existing Auth
server identity verifier. Only after successful verification does it inspect the
bounded JWT payload. It binds subject, exact trusted issuer, authenticated role/
audience, AAL2, session UUID, issue/expiry/not-before times and one TOTP AMR entry.
User/app metadata never supplies a business role, grant or MFA proof.

Every verification reads current server session evidence. The separate Supabase
adapter uses parameterized, column-specific SELECT against auth.sessions, users,
mfa_factors and mfa_amr_claims. The session must belong to the verified user, retain
AAL2 and a verified same-user TOTP factor, and have an unexpired not_after. The
account must be non-anonymous, email-confirmed, undeleted and not currently banned.
The factor must predate the server MFA event. The token's MFA second must match
the server AMR updated_at second, as generated by Supabase Auth. Removed sessions,
factors, AMR evidence and downgraded sessions deny even with an unexpired token.

The caller must explicitly supply a freshness window from 1 to 900 seconds; this
is a technical ceiling, not an approved business default. Expiry is checked again
after asynchronous work. An immutable internal proof expires at the earliest of
token, freshness or session expiry. It supplies no business authority. Do not
persist/cache a proof, use it as an HTTP credential or reuse it on another action.
Provider/database failures become generic identity-unavailable errors; invalid or
ineligible evidence denies without leaking tokens or SQL details.

This module has no runtime wiring, environment switch, database login, new grant,
public RPC or migration. The existing assignment loader still supplies AAL1 and
no grants. The provider adapter requires a separately reviewed project-specific
executor with minimal column SELECT, timeouts and secure credentials/CA. Never
give application code owner/service-role privileges to make the query work. Auth
schema access is provider-specific and stays outside portable business services.

The local script scripts/session-step-up-db-check.mjs connects only to the
disposable password-protected 127.0.0.1:54329 replay cluster and refuses an existing
auth schema. Synthetic provider-shaped tables, a NOLOGIN read-only role and all
fixtures roll back. It tests real PostgreSQL query semantics, not Auth signatures,
enrollment, email, MFA challenge, refresh, global logout or genuine provider policy.

Genuine provider acceptance, effective inactivity/timebox policy, other MFA methods,
MFA recovery, concurrency/in-flight revocation semantics and an audited privileged
writer remain open. A read cannot cancel an action after a later revocation; the
future writer must reverify per action and define its transaction/locking boundary.
Do not enable this foundation before those checks and the Node advisory gate are
resolved. Eleven local/ten hosted migrations remain unchanged; the role-assignment
migration is still unapplied. Phase 1 remains PARTIAL.
